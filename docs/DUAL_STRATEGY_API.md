# 当日策略双 Agent

入口：React「当日策略」。原股票研究入口合并至此；旧研究记录仍保存在原数据文件中，旧规则报告不作为 Agent 卡片显示。标的通过 Binance 实时 USDT 永续合约目录核验。

每个合约/周期分别执行策略1（流动性扫荡）和策略2（缠论）。流程实现在 agent_runtime.py：

1. 规划 Agent：真实模型调用，提出核查重点和最多三个 RAG 问题。
2. 工具：读取已收盘 OHLCV、行情快照，计算结构；缠论按模型问题检索视频原文。
3. 分析 Agent：真实模型调用，产出结构化方向、入场、SL、TP1/TP2/TP3、证据引用与失效条件。
4. 复核 Agent：独立模型调用，对相同事实和分析提案进行审查。
5. 本地点位校验：字段、有限数、方向顺序、证据 ID。账户余额、杠杆、评分、盈亏比、ATR等阈值不参与 Agent 判断或拦截，也不再展示对应设置。

策略卡新增 execution 和 trigger：READY 表示模型判断已满足条件；CONDITIONAL 表示带方向及具体点位的待触发计划。未确认信号优先输出条件策略，只有确实无法形成有依据计划时 UNAVAILABLE。飞书同步展示触发条件。每个合约保留 CoinGlass 清算热力图外链入口；外部页面数据未自动输入模型。

这些 Agent 是同一已配置模型承担不同职责的有界编排，不是不同服务商模型投票。正常每套三次、每合约两套共六次模型调用。工具不会自行生成交易方向或补齐止盈。无 API、调用失败、证据缺失、复核拒绝、点位校验未通过均不能产生可推送方向卡片。执行记录展示简短核查结果与证据，不要求或保存模型隐式思维链。

接口：`analyze_daily_agents({watch_item:{symbol,timeframe}})` 手动生成两套卡片、不推送；`agent_status()` 查询配置与历史；`configure_agent(payload)` 保存配置；`agent_contract_catalog({refresh:true})` 实时核验目录；`start_agent_monitor({})`/`stop_agent_monitor()` 管理自动运行。

自动运行按每个合约/周期/策略的新收盘 K 去重；模型失败也等待下一根 K，避免重复消耗额度。修改配置或密钥会清除去重记录。手动生成总是重新分析。自动运行只有方向、复核及风控通过、推送开关开启且已配置飞书时才发送卡片。不会自动下单。停止请求不取消已经发出的 HTTP 请求，但阻止后续推送和下一轮分析。

API Key 只保存在后端进程内存；重启需重新输入。前端密码框，留空保留；提供方切换清空旧 Key。DeepSeek/OpenAI 使用官方固定接口，模型 ID 可编辑。飞书地址与签名同样在内存。连接测试是一次真实 API 调用，与策略分析分开。

边界：缠论工具当前确认范围为方向去包含、严格分型、严格笔；不是完整 Pine 线段/中枢/背驰引擎的移植。RAG 提供视频理论依据，不证明行情出现买卖点；模型不能把未提供的高级结构声称为程序已确认。流动性使用 OHLCV 扫荡收回代理，不等于真实订单流或清算成交数据。模型评分不是胜率。

验证：18 项后端 Agent 测试、2 项桥接测试、7 项 React 工作流测试通过；测试模型为可控桩，不能替代真实 API 连通与策略质量验证。
